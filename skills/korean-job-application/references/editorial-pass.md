# 복잡한 집필의 편집 패스

기존 **사실 확인 → 소재·논지 선택 → 집필 → 검토·분량 조정** 중 마지막 단계에서, 사실에 맞는 초안의 설득력까지 다시 판단하는 방법이다. 별도 모드 선택이나 심사표 작성을 사용자에게 요구하지 않는다.

## 언제 분리할지

다음 중 실제로 해당할 때만 읽고 적용한다.

- 사용자가 작성 후 별도 편집 검토나 충분히 다듬은 완성본을 명시적으로 요청했다.
- 여러 후보가 필수 요구를 충족하지만 강조할 판단이 달라 선택이 어렵다.
- 복합 문항·여러 문항의 전체 재작성에서 한 요구를 살리는 편집이 다른 요구·기여·목소리를 훼손할 위험이 있다.

단순 오탈자, 지정 문장 수정, 충분하고 명료한 짧은 초안은 기존 내부 검토로 끝낸다. 글이 길다는 이유만으로 분리하지 않는다. 해결 안 된 사실 공백을 편집자에게 추측하게 하지 않는다.

## 실행 환경에 맞는 분리

독립 호출이 가능한 하위 agent 도구와 필요한 권한이 있고, 위 이유로 분리의 이득이 있으면 **집필 후 편집자 한 명**에게 판단을 맡긴다. 현재 허용된 실행 환경 안에서만 사용하며 새 서비스·계정·유료 API나 모델 변경을 자동으로 요구하지 않는다. 공개 사이트나 외부 사람에게 지원자 자료를 보내지 않는다. 사용자가 외부 전달이나 위임을 제한했으면 따른다.

그 도구가 없거나 허용되지 않거나 실행 한도에 걸리면 동일 agent가 집필을 마친 뒤 아래 기준으로 별도 편집 패스를 수행한다. 이를 독립 평가나 사람 전문가 검토라고 부르지 않는다. 도구 부재 때문에 작성 결과를 중단하거나 설치를 요구하지 않는다.

## 편집자에게 줄 최소 자료

문항 원문·공고의 관련 과업, 사용자의 출력·분량·문체·수정 범위, 관련 입력 사실과 확인 상태, 목소리 표본이 있으면 해당 부분, 작성된 초안을 전달한다. 요약에서 빠질 수 있는 역할·제약·반대 근거는 관련 원문 구절로 보존한다. 초안만 주고 사실성을 판정하게 하지 않는다.

집필자의 긴 설명이나 선호하는 승자를 주입하지 않는다. 편집자는 원자료·초안을 구별하고, 자기 제안도 새 사실의 출처가 아니라는 점을 따른다. 사용자가 쓰지 말라고 한 정보·문항과 무관한 신상·다른 지원자의 사례 본문은 전달하지 않는다. 파일 저장은 사용자가 요청한 경우만 한다.

다음은 복사해 상황에 맞게 채울 수 있는 편집자 요청이다. 누락된 입력을 임의로 채우지 않는다.

> 제공한 문항·과업·사실과 제약을 기준으로 초안을 검토해 주세요. 새 사실·조사·파일 작성·다른 agent 호출은 하지 마세요. 사실과 필수 요구 위반을 먼저 찾고, 그다음 중심 주장·판단의 설명·직무 연결·작성자 목소리가 실제로 더 선명해질 편집만 제안하세요. 살릴 구간과 바꿀 구간을 구별하고, 각 제안에는 대상 구절, 문항상 이유, 사용할 입력 근거를 붙이세요. 현재 제약 안에서 더 나은 수정이 없으면 유지라고 해주세요. 누락된 핵심 정보는 질문 후보로 남기고, 주장할 근거 없는 효과나 막연한 취향은 개선 사유로 쓰지 마세요. 근거 있는 편집 의견을 반환하면 종료하세요.

## 문장이 맞아도 평범할 때 볼 것

| 결정 | 판단할 실제 차이 |
| --- | --- |
| 중심 주장 | 어느 활동에 참여했는지뿐 아니라 질문이 묻는 선택·일하는 방식·기여를 근거로 알 수 있는가 |
| 설명의 연결 | 행동을 나열한 것인가, 입력에 있는 제약·관찰 때문에 그 행동을 고른 이유가 드러나는가 |
| 근거의 우선순위 | 직무명·성과 규모·직책에 끌려 문항에 더 직접 답하는 다른 근거를 밀어내지 않았는가 |
| 문단과 분량 | 같은 결론을 반복하는 부분 대신 필수 요구의 필요한 설명을 담을 수 있는가 |
| 목소리 | 작성자의 관점·구체 동사를 보존하는가, 추상적인 취업 문구로 바꾸는 데 그치지 않는가 |

원문이 이미 답하고 있으면 다시 쓰지 않는 것도 편집 결정이다. 서로 가능한 논지를 비교할 때는 [어려운 대조](examples/editorial-tradeoffs.md), 정보 재배치와 추가 확인의 경계는 [공개 첨삭 판단](expert-editing-notes.md)을 필요할 때만 읽는다. 모든 기준에서 결함을 찾거나 점수를 합산하지 않는다.

## 집필자가 반영하고 끝내는 기준

편집 의견을 자동 수용하지 않는다. 사용자 요구, 제공 사실, 기존의 좋은 연결을 확인해 **반영 / 기존안 유지 / 사용자 확인 필요** 중 필요한 처리를 한다. 편집자의 수치·동기·역할 제안은 입력에 근거가 없으면 넣지 않는다. 의견이 문체 취향뿐이면 사용자의 목소리와 요청을 따른다.

기본은 초안 뒤 **한 번의 편집 의견과 한 번의 반영**이다. 반영 뒤 집필자가 사실·필수 요구·길이를 직접 다시 확인한다. 추가 독립 재검토는 반영 과정에서 중대한 결함이 새로 생겨 확인이 필요한 경우 한 번으로 제한한다. 만족할 때까지 agent를 늘리거나 승자가 나올 때까지 재생성하지 않는다. 끝내 해결되지 않는 핵심 사실은 기존 작업용 초안·질문 규칙으로 처리한다.

초안의 좋은 근거·요구 충족을 잃는 수정은 채택하지 않고 기존의 좋은 부분을 보존한다. 본문만 요청하면 최종 본문만 내며 작업용 상태 표식 예외는 유지한다. 검토 과정 공개가 요청됐다면 실제 수행한 방식과 중요한 반영·유지 이유만 설명한다. 단순한 역할 분담을 전문가 승인·독립 사실 검증·합격 효과로 부르지 않는다.
