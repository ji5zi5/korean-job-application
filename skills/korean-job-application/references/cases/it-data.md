# IT·데이터 공개 지원서 관찰 사례

열람일: 2026-09-06. 아래는 공개 페이지에서 문항과 해당 답변 본문을 직접 읽은 짧은 관찰이다. 각 페이지의 `합격 자소서` 표시는 플랫폼이 붙인 표시(P1: 플랫폼 주장만 확인)이며, 채용 결과·지원자 사실·문장 특성이 합격을 일으켰다는 증거는 아니다. 원문, 지원자 프로필, 문장을 저장하거나 재현하지 않는다. `Q`는 실제 문항의 요구에만 붙였고, 답변에 우연히 등장한 주제로 확장하지 않았다.

## IT01 — CJ올리브영 / 소프트웨어 엔지니어 / 2025 상반기

- 원문: <https://linkareer.com/cover-letter/35131> · 열람일: 2026-09-06 · 표시: P1, 페이지 제목과 `합격 자소서` 표제 확인.
- 실제 문항 유형: Q08 가치·자기표현, Q02 직무 역량, Q12 서비스 개선 제안. 마지막 문항은 앱·웹·오프라인의 불편과 개발 방향을 요구하므로 Q12이다.
- 관찰: 접근성 문제를 발견한 계기→선택한 입력 방식→검증 결과로 연결하고, 서비스 제안도 이용 흐름의 관찰에서 기능·구현 방향으로 이어 간다.
- 한계: 제안의 효과는 미래 가설이며 운영 데이터나 구현 제약의 근거가 충분히 보이지 않는다. 수치가 있어도 측정 조건과 본인 기여는 별도 확인 대상이다.
- 재사용 원칙·수리 후보: P01/P04/P05/P06; QF01, EV04, CO01, CA01, EV06. 관찰→선택 이유→검증 범위를 쓰고, 제안은 완료 성과처럼 쓰지 않는다.

- 재사용 원칙·수리 후보: P01/P02/P06/P07; QF04, QF06, EV06, CO03, CL02, CL06. 회사 사실은 최소화하고 자기 경험의 판단과 산출물을 먼저 쓴다.

- 한계: 여러 프로젝트·학습·기술 설명이 한 답에 과밀해 핵심 사건의 개인 결정과 결과가 분산된다. 대규모 트래픽 관련 부분은 실제 경험과 학습 내용을 구별해야 한다.
