# Q01·Q02 완결 시연

아래 여덟 개 중 이 파일의 네 시연은 **순수하게 만든 가상 지원자·가상 공고·가상 경험**이다. 실제 지원자, 실제 기업, 공개 지원서의 사실이나 문장을 옮긴 사례가 아니다. A는 필요한 사실이 이미 충분할 때의 완성 초안이고, B는 부족한 입력을 질문 또는 편집 판단과 사용자의 추가 답변으로 해소한 뒤에만 수정본을 낸다.

## 공통 연속 시연에 고정한 입력 — Q01A·Q02A·Q04A

아래 네 경험과 두 공고, 두 동기는 Q01A·Q02A·다음 파일의 Q04A가 함께 쓰는 가상 사실이다. 각 답안은 이 중 문항에 필요한 경험만 고르며, 다른 사실을 새로 보태지 않는다.

| 경험 | 가상 지원자 사실 |
| --- | --- |
| 접수 운영 | 지역 청소년센터 방학 프로그램 접수를 지원하며 신청서의 중복 기재를 발견했다. 팀에 알리고, 제출 전 확인 항목을 넣은 안내문 초안을 만들었다. 다음 접수에서 팀은 중복 기재 관련 문의가 줄었다고 관찰했다. 비율은 측정하지 않았다. |
| 팀 과제 | 수업 팀 과제에서 자료 정리 일정이 늦어지자 작업 목록을 나누고 팀원들과 마감 순서를 다시 정했다. 수정한 일정표를 공유했고, 팀은 최종 보고서를 제출했다. |
| 매장 보조 | 가상 매장에서 반복 질문을 문의 유형으로 정리해 인수인계 메모에 반영했다. 다음 근무자는 메모를 보고 문의 내용을 확인했다. |
| 수업 분석 | 제공 자료에서 누락값을 발견해 팀원들과 분석 제외 범위를 확인하고, 제외 이유를 발표 자료에 적었다. 팀은 자료를 바탕으로 발표를 제출했다. |

**가상 제공 공고 — 온결 데이터운영:** 입력 자료 오류 확인, 관련 담당자와의 일정 조율, 오류 기록 방식 활용을 요구한다.  
**가상 제공 공고 — 이음 고객운영:** 문의 기록의 정확성 확인, 담당자에게 이관할 정보 정리, 고객 응대 과정의 개선 제안을 요구한다.

추가 가상 지원자 동기도 사용 전에 고정한다. 지원자는 접수 운영을 통해 재확인 기준을 남기는 운영 업무를 선택하고 싶다고 했고, 매장 보조를 통해 다음 담당자가 문의 맥락을 빠르게 파악하도록 돕는 일에 관심을 갖게 됐다고 말했다.

## Q01A — 제공 공고와 경험을 구분한 지원동기

### 입력 사실

- [공통 가상 지원자 사실] 위 공통 입력의 접수 운영 경험을 쓴다.
- [공통 가상 제공 공고] 위 공통 입력의 `온결 데이터운영` 업무를 쓴다.
- [공통 가상 지원자 동기] 위 공통 입력의 접수 운영 기반 동기를 쓴다.

### 문항 요구

`온결 데이터운영에 지원한 이유와 준비한 역량을 설명해 주세요.`

### 선택 이유

접수 경험은 공고의 오류 확인·기록 방식과 직접 맞닿아 있고, 지원자의 행동과 팀의 관찰 결과를 구분해 설명할 수 있다. 공고가 제공되었으므로 회사 고유 사실을 새로 조사하지 않는다.

### 완성 초안

반복되는 오류를 발견한 뒤 다음 사람이 확인할 기준을 남기는 운영 업무를 하고 싶어 지원했습니다. 지역 청소년센터의 방학 프로그램 접수를 지원할 때 신청서에서 중복 기재를 발견했습니다. 저는 팀에 해당 사실을 알린 뒤, 신청자가 제출 전에 확인할 항목을 넣은 안내문 초안을 만들었습니다. 다음 접수에서 팀은 중복 기재와 관련한 문의가 줄었다고 관찰했지만, 감소 비율은 측정하지 않았습니다. 제공 공고의 입력 자료 오류 확인과 오류 기록 방식 활용 업무는 이 경험에서 제가 중요하게 배운 확인 기준을 실무에서 이어 갈 수 있는 지점이라고 판단했습니다. 관련 담당자와 정보를 맞추며 오류를 기록하는 방식도 배우겠습니다.

## Q01B — 회사 선택 근거가 없는 지원동기

### 문제 입력

`저는 꼼꼼하고 책임감이 강해 데이터 운영 직무에 적합합니다. 접수 업무를 하며 안내문도 정리했습니다. 귀사의 성장 가능성이 높아 지원했습니다.`

사용자는 회사명만 말했으며, 공고 내용·회사 선택 이유·안내문을 왜 고쳤는지·확인된 결과는 주지 않았다.

### 필요한 질문 또는 편집 판단

`성장 가능성`은 근거 없는 회사 사실이므로 삭제한다. 완성 답안을 쓰려면 제공 공고에서 지원 결정을 바꾼 업무 한 가지와, 안내문을 정리한 본인 행동 및 그 경험이 만든 직무 관심을 확인해야 한다.

### 가상의 추가 답변

- [가상 제공 공고] `푸른길 운영지원`은 신청 정보의 누락을 확인하고, 담당자에게 확인이 필요한 내용을 정리해 전달하는 업무를 제시한다.
- [가상 지원자 사실] 지원자는 봉사활동 신청서에서 빠진 연락 방법 항목을 발견해 담당자에게 알렸다. 이후 제출 전 확인 항목을 안내문에 넣었고, 다음 신청 접수에서 담당자는 빠진 항목을 확인하기 쉬웠다고 말했다.
- [가상 지원자 동기] 지원자는 누락을 대신 추측하기보다 확인할 내용을 정리해 전달하는 일이 운영 지원 직무와 맞는다고 느꼈다.

### 수정 결과

신청 정보의 빈칸을 추측으로 채우지 않고, 확인할 내용을 정리해 다음 담당자에게 전달하는 운영 지원 업무를 하고 싶어 지원했습니다. 봉사활동 신청서를 확인하던 중 연락 방법 항목이 비어 있는 사례를 발견해 담당자에게 알렸습니다. 저는 제출 전 확인할 항목을 안내문에 넣었고, 다음 접수에서 담당자는 빠진 항목을 확인하기 쉬웠다고 말했습니다. 제공 공고의 신청 정보 확인과 담당자 전달 업무는 이 경험에서 제가 맡았던 확인·정리 방식과 직접 연결됩니다. 입사 후에도 확인이 필요한 정보를 분명히 남기는 방식으로 업무를 익히겠습니다.

### 한계

이 답안은 제공된 가상 공고의 업무만 회사 근거로 쓴다. 실제 기업의 성장성·문화·성과는 확인하지 않았고, 담당자의 말은 누락률 감소를 뜻하지 않는다.

## Q02A — 도구 이름 대신 검토 판단을 보인 직무역량

### 입력 사실

- [공통 가상 지원자 사실] 위 공통 입력의 수업 분석 경험을 쓴다.
- [공통 가상 제공 공고] 위 공통 입력의 `온결 데이터운영` 업무를 쓴다.

### 문항 요구

`지원 직무에 필요한 역량을 보여 주는 경험과 그 결과를 설명해 주세요.`

### 선택 이유

누락값을 임의로 채우지 않고 분석 범위를 기록한 행동이 입력 오류 확인 업무와 직접 연결된다. 완성한 팀 발표는 결과로 쓰되, 발표 평가나 분석 정확도 향상은 제공되지 않았으므로 쓰지 않는다.

### 완성 초안

데이터를 다룰 때 값의 개수만 맞추기보다, 사용할 수 없는 값을 어떻게 처리했는지 남기는 역량을 길렀습니다. 수업 데이터 분석 과제에서 제공 자료의 누락값을 발견했을 때 저는 값을 추정해 넣지 않았습니다. 대신 팀원들과 분석에서 제외할 범위를 확인하고, 제외한 이유를 발표 자료에 적었습니다. 팀은 이 자료를 바탕으로 발표를 제출했습니다. 이 경험으로 오류를 발견한 뒤 처리 기준을 기록해야 다음 검토에서도 판단의 근거를 확인할 수 있다는 점을 배웠습니다. 제공 공고의 입력 자료 오류 확인과 기록 방식 활용 업무에서도, 확인한 범위와 제외 이유를 분명히 남기는 방식으로 기여하겠습니다.

## Q02B — 수강·도구 나열을 실제 행동으로 고친 사례

### 문제 입력

`엑셀과 파이썬을 배워 데이터 분석 역량을 갖췄습니다. 여러 프로젝트를 하며 문제 해결 능력도 키웠습니다.`

### 필요한 질문 또는 편집 판단

도구명과 `문제 해결 능력`만으로는 어떤 자료를 보고 무엇을 바꾸었는지 알 수 없다. 모든 프로젝트를 나열하지 말고, 도구를 실제로 사용한 한 과업의 입력·판단·산출물과 확인 방식을 묻는다.

### 가상의 추가 답변

- [가상 지원자 사실] 학과 행사 신청 목록을 정리할 때 지원자는 스프레드시트의 같은 이름·연락 방법 조합을 표시했다. 중복으로 표시된 행은 담당자에게 확인하도록 따로 목록을 만들었다. 담당자는 그 목록으로 확인 전화를 했으며, 지원자는 중복 여부를 결정하거나 신청을 삭제하지 않았다.
- [가상 제공 공고] `이음 고객운영`은 문의 기록의 정확성 확인과 담당자에게 넘길 정보의 정리를 업무로 제시한다.

### 수정 결과

기록을 분석할 때 중요한 것은 도구 자체보다 확인이 필요한 정보를 구분하는 일이라고 생각합니다. 학과 행사 신청 목록을 정리하며 스프레드시트에서 같은 이름과 연락 방법 조합을 표시했고, 중복으로 보이는 행은 담당자가 확인할 수 있도록 별도 목록으로 만들었습니다. 담당자는 그 목록을 바탕으로 확인 전화를 했습니다. 저는 중복 여부를 결정하거나 신청을 삭제한 것이 아니라, 확인이 필요한 대상을 정리한 역할을 맡았습니다. 제공 공고의 문의 기록 정확성 확인과 담당자 전달 정보 정리 업무에서도 이처럼 판단이 필요한 항목을 구분해 전달하겠습니다.

### 한계

이 경험은 스프레드시트 사용과 확인 대상 정리의 근거다. 데이터 분석 성과, 자동화 경험, 중복 건수 감소를 뒷받침하지는 않는다.

## 연속 시연 1/2 — 세 문항 세트의 공통 사실·배치·A사 답안

이 시연도 **순수 가상**이다. 위의 네 경험, 공고, 동기는 이 절에서 처음 제공된 사실이며 실제 지원자 프로필이나 실제 파일이 아니다. 다음 파일 [Q03·Q04 완결 시연](problem-teamwork.md)에서 같은 사실을 이어 쓴다.

### 가상 온결 데이터운영 Q01 완성 답안

반복되는 오류를 발견한 뒤 다음 사람이 확인할 기준을 남기는 운영 업무를 하고 싶어 지원했습니다. 지역 청소년센터의 방학 프로그램 접수를 지원할 때 신청서에서 중복 기재를 발견했습니다. 저는 팀에 해당 사실을 알린 뒤, 신청자가 제출 전에 확인할 항목을 넣은 안내문 초안을 만들었습니다. 다음 접수에서 팀은 중복 기재와 관련한 문의가 줄었다고 관찰했지만, 감소 비율은 측정하지 않았습니다. 온결 데이터운영이 제시한 입력 자료 오류 확인과 오류 기록 방식 활용 업무는 이 경험에서 제가 중요하게 배운 확인 기준을 실무에서 이어 갈 수 있는 지점이라고 판단했습니다.

### 가상 온결 데이터운영 Q02 완성 답안

데이터를 다룰 때 값의 개수만 맞추기보다, 사용할 수 없는 값을 어떻게 처리했는지 남기는 역량을 길렀습니다. 수업 데이터 분석 과제에서 제공 자료의 누락값을 발견했을 때 저는 값을 추정해 넣지 않았습니다. 대신 팀원들과 분석에서 제외할 범위를 확인하고, 제외한 이유를 발표 자료에 적었습니다. 팀은 이 자료를 바탕으로 발표를 제출했습니다. 온결 데이터운영이 제시한 입력 자료 오류 확인과 기록 방식 활용 업무에서도, 확인한 범위와 제외 이유를 분명히 남기는 방식으로 기여하겠습니다.

다음 파일에서 A·B사 Q04 답안, B사 변형, 사용자가 요청한 MD/TXT와 이동용 경험 요약의 **내용 예시**를 계속한다. 이 문서 자체는 파일 생성 시연이 아니므로 MD·TXT 파일을 실제로 만들지 않는다.
