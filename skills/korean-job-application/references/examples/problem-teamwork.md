# Q03·Q04 완결 시연

아래 시연은 **순수하게 만든 가상 지원자·가상 공고·가상 경험**이다. 실제 지원자, 실제 기업, 공개 지원서의 사실이나 문장을 재사용하지 않는다. A는 충분한 입력에서 완성 초안을 바로 쓰고, B는 부족한 입력을 그대로 완성본처럼 만들지 않는다.

## Q03A — 원인 확인과 조치의 범위를 지킨 문제해결

### 입력 사실

- [가상 지원자 사실] 학과 공동 장비 대여를 지원할 때 두 개의 대여 목록에서 반납 예정일이 다르게 적힌 사례를 발견했다. 지원자는 어느 목록이 맞는지 단정하지 않고, 원래 신청 기록과 대여 담당자의 확인을 거쳐 기준 목록을 정했다. 이후 담당자가 두 목록을 함께 확인할 수 있도록 확인 순서를 적은 메모를 만들었다.
- [가상 결과] 다음 대여 준비에서 담당자는 메모를 사용해 두 목록을 함께 확인했다. 오류가 얼마나 줄었는지는 측정하지 않았다.

### 문항 요구

`문제를 발견하고 개선한 경험을 문제 인식, 행동, 결과의 순서로 설명해 주세요.`

### 선택 이유

문제 신호, 확인 근거, 지원자의 권한 범위, 조치와 정성 결과가 모두 제공됐다. 지원자는 반납일을 독자적으로 결정한 것이 아니라 확인 절차를 제안·정리한 범위로 쓴다.

### 완성 초안

공동 장비 대여를 지원하면서 반납 예정일이 서로 다른 두 목록을 발견했습니다. 어느 목록이 맞는지 추측하면 대여 안내가 더 혼란스러워질 수 있다고 판단해, 원래 신청 기록과 대여 담당자의 확인을 먼저 거쳤습니다. 확인 뒤에는 다음 준비에서도 같은 순서로 두 목록을 대조할 수 있도록 확인 절차를 메모로 정리했습니다. 이후 대여 준비에서 담당자는 이 메모를 사용해 두 목록을 함께 확인했습니다. 문제를 임의로 처리하지 않고 확인 기준을 남겨 다음 작업에 활용할 수 있게 한 경험이었습니다.

## Q03B — 측정 근거 없는 개선율을 삭제한 사례

### 문제 입력

`저는 행사 접수 절차를 개선해 오류를 크게 줄였습니다. 팀원들이 제 방식이 좋다고 했고, 이후 업무 효율도 높아졌습니다.`

입력에는 어떤 오류인지, 지원자가 무엇을 했는지, `크게`와 `높아졌다`의 기준이 제공되지 않았다.

### 필요한 질문 또는 편집 판단

근거 없는 개선율·평가를 보태지 않는다. 오류의 신호, 지원자 책임 범위, 실제 조치, 조치 뒤 확인된 산출물 또는 관찰을 한 번에 확인한다. 이 정보가 없으면 결과 문장을 제거한 작업용 초안으로 멈춘다.

### 가상의 추가 답변

- [가상 지원자 사실] 동아리 행사 접수에서 선택 항목을 비워 제출하는 사례가 있었다. 지원자는 운영팀의 결정권자가 아니었고, 빈 항목을 확인하도록 표시한 목록을 만들었다. 운영팀은 이 목록을 보고 참가자에게 확인을 요청했다.
- [가상 결과] 다음 접수 때 운영팀은 같은 목록 형식으로 빈 항목을 확인했다. 감소율·처리 시간·팀원 평가 내용은 기록되지 않았다.

### 수정 결과

동아리 행사 접수에서 선택 항목을 비워 제출하는 사례를 발견했을 때, 저는 운영팀이 확인할 수 있도록 빈 항목을 표시한 목록을 만들었습니다. 운영팀은 이 목록을 보고 참가자에게 확인을 요청했습니다. 다음 접수에서도 운영팀은 같은 목록 형식으로 빈 항목을 확인했습니다. 저는 절차를 결정하는 역할은 아니었지만, 확인이 필요한 대상을 보이게 정리해 운영팀의 후속 확인을 도왔습니다.

### 한계

목록이 오류를 줄였다는 인과나 효율 향상은 확인되지 않았다. 이 사례는 지원자의 정리 행동과 운영팀의 후속 사용까지만 보여 준다.

## Q04A — 역할·의존성을 드러낸 협업

### 입력 사실

- [공통 가상 지원자 사실] [Q01·Q02 완결 시연](motivation-competency.md)에 먼저 고정한 팀 과제 경험을 쓴다.
- [공통 가상 팀 사실] 위 팀 과제에서 다른 팀원들은 각자 맡은 자료 정리와 발표 자료 작성을 갱신했고, 팀은 최종 보고서를 제출했다.
- [공통 가상 제공 공고] 위 공통 입력의 `온결 데이터운영` 일정 조율 업무를 쓴다.

### 문항 요구

`공동 목표를 위해 다른 사람과 협업한 경험에서 본인의 역할과 결과를 설명해 주세요.`

### 선택 이유

이 팀 과제에는 공동 목표, 지원자의 조율 행동, 다른 팀원의 작업, 팀 결과가 구분돼 있다. 갈등의 승패가 아니라 일정 의존성을 어떻게 공유했는지를 중심으로 쓴다.

### 완성 초안

수업 팀 과제에서 자료 정리 일정이 늦어지며 발표 자료 작성 순서까지 영향을 받았습니다. 저는 작업 목록을 나누어 어느 자료가 먼저 정리돼야 다음 작업을 시작할 수 있는지 팀원들과 확인했습니다. 이후 마감 순서를 다시 정한 일정표를 공유했습니다. 다른 팀원들은 각자 맡은 자료 정리와 발표 자료 작성을 갱신했고, 팀은 최종 보고서를 제출했습니다. 저는 일정표를 만들고 공유하는 역할을 맡았으며, 보고서 제출은 팀의 공동 결과입니다. 제공 공고의 관련 담당자 일정 조율 업무에서도 작업의 의존성을 먼저 보이게 하고, 확인된 순서를 공유하는 방식으로 협업하겠습니다.

## Q04B — `우리` 속 개인 행동을 복원한 사례

### 문제 입력

`팀원들과 의견 충돌이 있었지만 잘 설득해서 성공적으로 발표했습니다. 저는 소통 능력이 좋다는 평가를 받았습니다.`

### 필요한 질문 또는 편집 판단

누가 어떤 제약을 가졌는지, 지원자가 실제로 한 조율 행동이 무엇인지, 팀 결과와 개인 기여가 무엇인지 확인해야 한다. `잘 설득했다`와 `소통 능력 평가`는 근거가 없으므로 그대로 쓰지 않는다.

### 가상의 추가 답변

- [가상 지원자 사실] 팀 발표에서 자료 조사 담당과 발표 자료 담당이 같은 날 마감을 원해 순서가 겹쳤다. 지원자는 결정 권한이 없었지만 각 담당자가 필요한 파일과 마감 시점을 표로 정리했다.
- [가상 팀 사실] 팀원들은 표를 보고 자료 정리를 먼저 마치고 발표 자료를 이어서 만들기로 합의했다. 팀은 발표 자료를 제출했다.

### 수정 결과

팀 발표를 준비하며 자료 조사 담당과 발표 자료 담당의 마감 순서가 겹쳤습니다. 저는 결정 권한을 대신 행사하지 않고, 각 담당자가 먼저 받아야 하는 파일과 마감 시점을 표로 정리했습니다. 팀원들은 그 표를 보고 자료 정리를 먼저 마친 뒤 발표 자료를 이어서 만들기로 합의했습니다. 저는 의존 관계를 보이게 정리한 역할을 맡았고, 발표 자료 제출은 팀의 공동 결과였습니다. 이 경험을 통해 협업에서는 의견을 이기기보다 각자의 작업 조건을 확인할 수 있게 하는 것이 먼저라는 점을 배웠습니다.

### 한계

제공된 사실에는 발표 평가나 지원자의 소통 능력에 대한 피드백이 없다. 따라서 성공적 발표나 개인 역량 평가로 확대하지 않는다.

## 연속 시연 2/2 — Q04 답안·회사별 변형과 요청 출력

이 절은 [Q01·Q02 완결 시연의 연속 시연 1/2](motivation-competency.md)을 이어 간다. 그 파일에서 고정한 네 경험, 두 가상 공고, 두 가상 지원자 동기만 사용한다. 회사가 달라도 경험의 역할·행동·결과는 바꾸지 않는다.

### 가상 온결 데이터운영 Q04 완성 답안

수업 팀 과제에서 자료 정리 일정이 늦어지며 발표 자료 작성 순서까지 영향을 받았습니다. 저는 작업 목록을 나누어 어느 자료가 먼저 정리돼야 다음 작업을 시작할 수 있는지 팀원들과 확인했습니다. 이후 마감 순서를 다시 정한 일정표를 공유했습니다. 다른 팀원들은 각자 맡은 자료 정리와 발표 자료 작성을 갱신했고, 팀은 최종 보고서를 제출했습니다. 저는 일정표를 만들고 공유하는 역할을 맡았으며, 보고서 제출은 팀의 공동 결과입니다. 온결 데이터운영이 제시한 관련 담당자와의 일정 조율 업무에서도 작업의 의존성을 먼저 보이게 하고, 확인된 순서를 공유하는 방식으로 협업하겠습니다.

이로써 온결 데이터운영에는 지원동기에 접수 운영의 확인 기준, 직무역량에 수업 분석의 누락값 처리 기준, 협업에 팀 과제의 일정 조율을 배치했다. 동일한 사실을 반복 서술하지 않고 문항별 질문을 나눴다.

### 가상 이음 고객운영 변형 답안

**Q01 지원동기**

다음 담당자가 문의 맥락을 빠르게 파악할 수 있게 돕는 고객 운영 업무를 하고 싶어 지원했습니다. 매장 근무를 보조할 때 반복 질문을 문의 유형으로 정리해 인수인계 메모에 반영했습니다. 다음 근무자는 그 메모를 보고 문의 내용을 확인했습니다. 이음 고객운영이 제시한 문의 기록 정확성 확인과 이관 정보 정리 업무는, 반복되는 내용을 다음 담당자가 확인할 수 있게 남긴 경험과 연결됩니다.

**Q02 직무역량**

신청서의 중복 기재를 발견했을 때 저는 팀에 해당 사실을 알리고, 제출 전 확인 항목을 넣은 안내문 초안을 만들었습니다. 다음 접수에서 팀은 중복 기재와 관련한 문의가 줄었다고 관찰했습니다. 이음 고객운영이 제시한 문의 기록 정확성 확인 업무에서도 확인이 필요한 항목을 구분해 담당자가 다시 볼 수 있게 하겠습니다.

**Q04 협업**

수업 팀 과제에서 자료 정리 일정이 늦어지자 저는 작업 목록을 나누고 팀원들과 마감 순서를 다시 정한 일정표를 공유했습니다. 다른 팀원들은 각자 맡은 자료 정리와 발표 자료 작성을 갱신했고, 팀은 최종 보고서를 제출했습니다. 저는 일정 조율 자료를 정리한 역할을 맡았습니다. 이음 고객운영이 제시한 담당자 이관 정보 정리 업무에서도 다음 사람이 필요한 정보를 확인할 수 있는 순서로 공유하겠습니다.

### 사용자가 요청한 MD·TXT와 이동용 경험 요약의 내용 예시

가상의 사용자가 `온결 지원 답안을 MD와 TXT로 저장하고, 다음 대화용 경험 요약도 보여 주세요.`라고 요청한 상황이다. 아래는 그 요청에 응답해 **표시할 내용의 예시**일 뿐이며, 이 참조 문서가 실제 `MD`·`TXT` 파일이나 요약 파일을 만들지는 않는다. 실제 실행에서는 사용자가 지정했거나 충돌하지 않는 새 경로에 두 형식을 각각 만들고 다시 읽어 확인한다.

**가상 MD 내용 예시 (`온결-지원답안.md`)**

```markdown
# 온결 데이터운영 지원 답안

## Q01 지원동기
반복되는 오류를 발견한 뒤 다음 사람이 확인할 기준을 남기는 운영 업무를 하고 싶어 지원했습니다. 지역 청소년센터의 방학 프로그램 접수를 지원할 때 신청서에서 중복 기재를 발견했습니다. 저는 팀에 해당 사실을 알린 뒤, 신청자가 제출 전에 확인할 항목을 넣은 안내문 초안을 만들었습니다. 다음 접수에서 팀은 중복 기재와 관련한 문의가 줄었다고 관찰했습니다. 온결 데이터운영이 제시한 입력 자료 오류 확인과 오류 기록 방식 활용 업무는 이 경험에서 제가 중요하게 배운 확인 기준을 실무에서 이어 갈 수 있는 지점이라고 판단했습니다.

## Q02 직무역량
데이터를 다룰 때 값의 개수만 맞추기보다, 사용할 수 없는 값을 어떻게 처리했는지 남기는 역량을 길렀습니다. 수업 데이터 분석 과제에서 제공 자료의 누락값을 발견했을 때 저는 값을 추정해 넣지 않았습니다. 대신 팀원들과 분석에서 제외할 범위를 확인하고, 제외한 이유를 발표 자료에 적었습니다. 팀은 이 자료를 바탕으로 발표를 제출했습니다. 온결 데이터운영이 제시한 입력 자료 오류 확인과 기록 방식 활용 업무에서도, 확인한 범위와 제외 이유를 분명히 남기는 방식으로 기여하겠습니다.

## Q04 협업
수업 팀 과제에서 자료 정리 일정이 늦어지며 발표 자료 작성 순서까지 영향을 받았습니다. 저는 작업 목록을 나누어 어느 자료가 먼저 정리돼야 다음 작업을 시작할 수 있는지 팀원들과 확인했습니다. 이후 마감 순서를 다시 정한 일정표를 공유했습니다. 다른 팀원들은 각자 맡은 자료 정리와 발표 자료 작성을 갱신했고, 팀은 최종 보고서를 제출했습니다. 저는 일정표를 만들고 공유하는 역할을 맡았으며, 보고서 제출은 팀의 공동 결과입니다. 온결 데이터운영이 제시한 관련 담당자와의 일정 조율 업무에서도 작업의 의존성을 먼저 보이게 하고, 확인된 순서를 공유하는 방식으로 협업하겠습니다.
```

**가상 이동용 경험 요약 내용 예시**

아래는 제출 본문이 아니라 다음 대화에 옮길 내부 요약이므로, 공통 사실표와 같은 E1~E4 식별자를 사용한다.

```markdown
# 경험 요약

## 사용자가 확인한 사실
- E1: 중복 기재 발견, 팀 알림, 확인 항목이 있는 안내문 초안, 팀의 정성 관찰.
- E2: 작업 목록 분리, 마감 순서 재조정, 일정표 공유, 팀의 최종 보고서 제출.
- E3: 반복 질문의 유형화, 인수인계 메모 반영, 다음 근무자의 메모 확인.
- E4: 누락값 발견, 분석 제외 범위 확인, 제외 이유 기록, 팀 발표 제출.

## 남은 확인 사항
- E1의 문의 변화 비율과 E3의 문의 처리 결과는 측정되지 않음.

## 문항별 사용 이력
- 온결 데이터운영 Q01: E1의 확인 기준 — 완성 초안.
- 온결 데이터운영 Q02: E4의 처리 기준 — 완성 초안.
- 온결 데이터운영 Q04: E2의 일정 조율 — 완성 초안.
- 이음 고객운영 Q01: E3의 인수인계 메모 — 완성 초안.

## 요청된 경우의 출처
- 온결 데이터운영·이음 고객운영 업무: 이 시연 안에서 제공된 가상 공고 문구만 사용.
```

이 흐름은 파일 생성 요청이 있어야 실제 파일을 만들고, 파일마다 다시 읽어 확인해야 한다는 경계를 보여 준다. 여기의 파일명·본문은 설명용 가상 예시이며 실제 생성 경로나 실제 파일의 존재를 주장하지 않는다.
