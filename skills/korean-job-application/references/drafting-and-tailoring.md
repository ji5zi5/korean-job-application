# 초안 작성과 직무 맞춤

이 문서는 지원자가 제공하고 확인한 사실을 문항에 맞는 한국어 초안으로 조직하는 작업 기준이다. 문장을 매끈하게 만드는 일보다, 질문이 요구하는 판단 근거와 지원자가 설명할 수 있는 경험을 먼저 맞춘다. 지원자의 경험·수치·날짜·회사 정보·전문 용어·감정·인과를 채워 넣지 않으며, 지원자가 요청하지 않은 조사나 저장을 하지 않는다.

사실의 다섯 상태(`confirmed`, `derived-with-basis`, `missing`, `contradicted`, `prohibited`)와 경험 카드의 정의는 [경험 정리·선택과 사실 계약](evidence-and-interview.md)에만 둔다. 이 문서는 그 기록을 실제 초안으로 바꾸는 단계이며, 별도의 사실 원장이나 새 상태 체계를 만들지 않는다.

## 출처와 적용 한계

- 국가보훈부 취업길라잡이의 자기소개서 작성방법: <https://job.mpva.go.kr/jobGdn/content04.do?menuKey=196> (열람일 2026-09-02). 질문 의도, 경험 중심의 구체성, 읽기 쉬운 구성은 참고 렌즈일 뿐 합격 예측이나 고정 형식의 근거가 아니다.

이 출처들은 작성 방법의 배경일 뿐 지원자 사실이나 회사 사실의 출처가 아니다. 이 문서만으로 외부 접근은 필요하지 않다.

## 우선순위와 작업 경계

제약이 충돌하면 다음 순서로 해결하며, 아래 순위의 지시를 조용히 무시하지 않는다.

1. 문항·공고의 명시 요구, 글자 제한, 제출 형식, 그리고 지원자가 제공한 블라인드 규칙
2. 지원자가 확인한 사실과 명시한 문체·수정 범위
3. 직무 맞춤에 허용된 검증 출처와 그 출처의 확인일
4. 이 문서의 진단 렌즈와 표현 제안

블라인드 규칙은 회사 맞춤보다 우선한다. 금지된 식별 단서는 묻지도, 표식 안에 반복하지도, 초안에 넣지도 않는다. 출처·사실·제약이 충돌하거나 모호하면 충돌 지점과 확인할 한 가지를 보여 주고, 안전한 범위를 넘는 문장은 만들지 않는다.

## 사실 기록에서 요청 분량 초안까지

작성 요청을 받으면 분석표를 반복해서 보여 주는 데서 멈추지 않는다. 내부적으로는 다음 흐름을 한 번 거친 뒤, 사실 수준에 맞는 초안을 낸다. 표·ID·원장은 사용자가 분석을 요청할 때만 보여 주며, 최종 본문만 요청하면 완성 본문만 돌려준다. 다만 미해결 핵심 사실이 있는 작업용 초안은 첫 줄의 상태 표식을 숨기지 않는다.

1. **사실을 기록한다.** 문항, 공고, 이미 받은 경험을 모두 읽고 공통 다섯 상태로 분류한다. `confirmed`와 근거가 남은 `derived-with-basis`만 서술 재료다. `missing`은 결과를 바꿀 때만 묻고, `contradicted`와 `prohibited`는 쓰지 않는다.
2. **논지를 고른다.** 문항의 하위 요구에 가장 직접 답하고 본인 행동·판단·근거가 선명한 주 에피소드와 핵심 답 한 가지를 고른다. 소재의 유명함, 숫자의 유무, 직무 키워드 일치만으로 고르지 않는다. 문항이 복수 사례를 요구하거나 비교·패턴·대조·변화 과정을 논증해야 할 때에는, 한 사례의 빈칸을 감추기 위한 것이 아니라는 전제에서 보조 에피소드를 더할 수 있다. 사용자가 한 사례로 제한했으면 그 제한을 따른다. [대조 작법](expert-writing-decisions.md)에서 해당 문항의 좋은 선택과 부족한 선택을 비교해, 독자가 이 지원자에 대해 알게 될 핵심과 그것을 설득하는 실제 근거를 정한다.
3. **초안을 쓴다.** 핵심 답 → 필요한 맥락 → 본인 판단과 행동 → 확인 가능한 결과 → 문항이 요구한 연결 순서로, 선택한 논지를 실제 문장으로 전개한다. 실제 실패·결과 범위·미해결 핵심 사실처럼 문항 해석에 필요한 한계는 남기되, 쓰지 않은 수치·성과나 과장 방지 같은 내부 점검은 본문에서 해설하지 않는다. 미래 시제로 제안임이 분명하면 제안이라는 설명을 되풀이하지 않는다. 구조 렌즈는 이 순서를 점검하는 선택지일 뿐 필수 문단 수나 입력량의 전제가 아니다.
4. **요청한 분량으로 완성한다.** 먼저 하위 요구와 사실의 누락을 고친 뒤, 그 다음에 중복·배경·표현을 줄이거나 필요한 설명을 보탠다. 글자 수 때문에 새로운 수치·인과·평가를 만들지 않는다. 입력 글자 수, 수정 횟수, 숫자 성과는 어느 단계의 필수 조건이 아니다.

회사 고유 사실이 필요한 논지라면 [요청한 기업 조사 절차](job-and-company-analysis.md#요청한-기업-조사-절차)를 따른다. 그 참조가 제공한 회사 사실은 지원자의 관심·선택 이유·감정을 증명하지 않는다. 지원자가 말하지 않은 동기나 회사 내부의 의도를 대신 정하지 않는다.

### 충분·부분·무경험 입력의 산출물

| 사실 수준 | 바로 할 일 | 사용자에게 줄 결과 |
| --- | --- | --- |
| 선택한 논지의 필수 사실이 모두 `confirmed` 또는 근거가 있는 `derived-with-basis`이고 모순이 없음 | 추가 인터뷰 없이 논지 선택과 집필을 끝낸다. | 요청 문항·분량의 **완성 초안**. 본문만 요청이면 본문만 준다. |
| 선택한 문항과 논지에 필요한 사실 중 일부가 비어 있음 | 확인된 범위에서 먼저 문장을 쓰고, 빠진 핵심 사실만 일반 표식으로 남긴다. | 첫 줄이 `작업용 초안 — 제출 전 확인 필요`인 **표시된 작업용 초안**과 가장 중요한 확인 한 가지. 표식 해소 전에는 완성본이나 분량 충족을 단정하지 않는다. |
| 쓸 에피소드가 전혀 없음 | 경험처럼 들리는 예문을 만들지 않는다. | 문항의 필수 요소를 담은 **뼈대**와, 다음 결과를 가장 크게 바꿀 필요한 질문 한 가지. |

역할명이나 “성실하게 했다” 같은 자기평가만으로는 에피소드가 생기지 않는다. 반대로 선택한 논지에 필요한 확인된 조각이 하나라도 있으면 그 범위를 넘지 않는 작업용 초안은 가능하다. 결과는 숫자일 필요가 없고, 확인 가능한 산출물·피드백·절차 변화도 충분한 근거가 될 수 있다. 선택한 문장에 필요하지 않은 날짜·수치·세부 칸의 공백만으로 작업용 초안으로 낮추지 않는다.

### 요청한 대안의 범위

대안은 사용자가 요청할 때만 낸다. 같은 사실을 반복해 말투만 바꾼 복사본 대신, 무엇이 달라졌는지를 짧게 밝힌다. 예를 들어 한 대안은 “문제 상황에서의 판단”을, 다른 대안은 “직무 적용”을 중심 논지로 삼거나, 한 대안은 결과를 먼저 제시하고 다른 대안은 상황에서 시작할 수 있다. 대안 사이의 경험 사실·역할·수치·회사 사실은 고정한다. 다른 사실이나 지원자 동기를 지어 내어 대안을 만들지 않는다.

## 문항 해체와 근거 매칭

초안을 쓰기 전에 문항 원문과 해석을 구분하여 아래 항목을 짧게 적는다.

| 확인 항목 | 확인할 내용 |
| --- | --- |
| 답해야 할 일 | 요구 행동·역량, 대상 직무·조직 맥락, 반드시 답할 하위 질문 |
| 제약 | 글자 수, 형식, 제출 지시, 블라인드 규칙, 지원자가 지정한 문체·범위 |
| 증명 기준 | 각 요구를 설득하는 상황·역할·행동·결과·산출물 또는 확인 방법 |
| 근거 매핑 | 사용할 주장 ID, 그 상태, 에피소드에서 맡을 위치, 남은 공백 |

주장 하나는 **확인된 사실 또는 허용된 파생**으로만 문장에 들어갈 수 있다. 허용된 파생은 이름 붙은 확인된 주장 ID에서 논리적으로 따라오는 요약일 뿐이며, 근거 ID를 함께 남긴다. 파생으로 날짜, 수량, 인과, 감정, 역량 평가, 회사 사실, 보호특성 추론을 새로 더하지 않는다. `missing`, `contradicted`, `prohibited` 상태의 주장은 서술하지 않고 확인 질문·표식·제외 사유로 처리한다.

문항의 각 필수 요소에 대해 다음 중 하나를 명시한다: (a) 이를 뒷받침하는 확인된 주장 ID, (b) 근거 ID가 적힌 허용된 파생, (c) 아직 없는 근거. (c)를 그럴듯한 키워드나 일반론으로 채우지 않는다.

## 에피소드 선택과 문단 의도

한 문항은 원칙적으로 요구 행동과 직접 연결되고, 본인 기여와 검증 근거가 가장 선명한 **주 에피소드** 하나를 깊게 쓴다. 선택 이유는 요구와의 직접성, 본인 역할, 행동의 구체성, 결과·산출물의 확인 가능성, 직무 연결의 근거로 설명한다.

**보조 에피소드**는 문항이 복수 사례를 요구하거나, 비교·패턴·대조·변화 과정의 논지를 위해 필요할 때 더할 수 있다. 사용자가 한 사례만 요구하거나 제한했으면 더하지 않는다. 근거가 빈약한 주 에피소드를 감추거나 한 사례만 요구한 문항의 분량을 채우기 위해 보조 에피소드를 넣지 않는다. 허용될 때에는 각 에피소드가 답하는 요구, 전환 이유, 두 사례의 관계를 밝혀야 한다.

각 문단에는 한 가지 의도를 붙인다. 예를 들어 질문에 대한 핵심 답, 필요한 배경, 문제·판단, 본인 행동, 결과의 근거, 직무 적용의 범위 중 무엇을 담당하는지 정한다. 배경·제약·행동·산출물·결과를 한 문장에 뒤섞지 않고, 문단의 의도와 근거 매핑에 없는 문장은 삭제하거나 확인 대상으로 남긴다.

문항이 `준비 과정`을 묻고 학습 내용이 필요한 지식·과업과 직접 연결되면 수강·자격 준비도 근거가 된다. `실제 수행 성과`를 묻는 경우와 구별하며, 경험을 강하게 보이게 하려고 학습을 실무 적용으로 바꾸지 않는다. 소재 자체가 요구를 충분히 뒷받침하지 못하면 문장 윤문만으로 해결됐다고 보지 않고 다른 후보나 핵심 사실을 확인한다.

## 선택 가능한 작성 렌즈

MPVA, STAR, 3C4P, KPI 관점, 헤드라인 우선, 회사-교체 점검은 문항과 근거를 살피는 선택적 렌즈다. 순서, 횟수, 문장 비율, 필수 문단 수를 강제하지 않는다.

- MPVA 또는 STAR는 상황·과제·행동·결과가 어디에서 빠졌는지 발견하는 데 쓸 수 있다.
- 3C4P와 KPI 관점은 제약, 판단, 산출물, 검증 가능성을 살피는 데 쓸 수 있다. 수치·KPI가 확인되지 않으면 새로 만들지 않는다.
- 헤드라인 우선은 답의 중심을 선명하게 할 때만 쓰며, 과장된 역량 평가는 피한다.
- 회사-교체 점검은 회사명을 바꾸어도 성립하는 일반론을 찾는 진단일 뿐, 특정 회사 사실을 덧붙이는 허가가 아니다.

## 표시된 작업용 초안의 표식

부분 초안은 반드시 첫 줄을 다음과 같이 시작한다.

> 작업용 초안 — 제출 전 확인 필요

근거가 비어 있는 자리는 `[확인 필요: 본인의 역할]`, `[확인 필요: 실제 행동]`, `[확인 필요: 결과의 확인 방법]`처럼 일반적인 표식으로 남긴다. 표식에는 학교명·지역·가족관계·사진·기관 식별 단서 등 블라인드 세부사항이나 그 밖의 금지 정보를 되풀이하지 않는다.

분량이나 글자 수 확인을 요청했으면 표식을 포함한 실제 제시 본문을 `scripts/count_chars.py`의 표준입력으로 내부 확인하고, 요청된 경우에만 적용 기준과 수치를 밝힌다. 표식만 뺀 별도 수치는 사용자가 원할 때만 계산한다. 사용자 본문은 명령행 인수로 넘기거나 자동 저장하지 않는다. 충분한 사실의 본문만 요청하면 수치·기준·검토표를 붙이지 않는다.

표식은 사실의 대용품이 아니다. **제출 전에 모든 표식을 확인하거나 제거**해야 하며, 그 전에는 제출용 전체 초안이나 제한 충족을 단정하지 않는다.

## 초안 전 내부 점검

아래 점검은 초안을 제출하기 전에 내부적으로 한다. 사용자가 검토표·근거 추적을 요청하지 않았다면 완성 초안에 문장별 감사표를 덧붙이지 않는다.

초안의 각 문장에 다음을 확인한다.

| 감사 항목 | 통과 조건 |
| --- | --- |
| 주장 근거 | 확인된 주장 ID 또는 그 ID가 적힌 허용된 파생으로 추적된다. 부분 초안의 빈칸은 일반 표식이다. |
| 기여·인과 | 팀의 일과 본인의 일을 구분하고, 확인되지 않은 원인·성과·역량 평가는 넣지 않는다. |
| 문항 적합 | 문장이 문항의 필수 요소나 문단 의도 하나를 실제로 돕는다. |
| 제약·블라인드 | 형식·길이·표현 범위와 블라인드 규칙을 위반하지 않는다. |
| 직무 연결 | 공고 요구와 지원자 근거의 연결이 보이며, 근거가 없으면 공백으로 보고한다. |
| 목소리·검증 | 지원자가 자기 경험으로 설명할 수 있고 확인할 수 있는 표현이다. |

감사에서 근거가 없는 문장은 삭제·표식·확인 질문 중 하나로 처리한다. 표현을 압축하거나 자연스럽게 다듬는 일은 이 감사의 근거를 늘리지 않는다. 과거 경험에는 실제로 한 일만 쓰고, 입사 후 활용·개선안은 미래의 제안임을 분명히 하며 과거 성과처럼 쓰지 않는다.

## 근거가 있는 직무 맞춤

관련 대조 예시: [Pair 6: evidence-based-tailoring](contrastive-examples.md#pair-6-evidence-based-tailoring).

직무 맞춤은 문항·공고의 요구와 지원자 근거를 한 항목씩 연결하는 일이다. 사용 가능한 회사·직무 정보는 (1) 사용자가 제공한 채용 공고, 또는 (2) 사용자가 명시적으로 요청한 현재 검증된 권위 있는 출처뿐이다. 후자의 경우 출처명, URL, 확인일, 초안에 쓰려는 구체적 사실을 기록한다. 정상 작업에서 조용히 회사를 조사하지 않는다.

맞춤의 정보 우선순위는 문항·블라인드·제출 제약, 사용자가 제공한 공고 원문, 사용자가 명시적으로 요청한 현재 검증된 권위 있는 출처, 지원자가 확인한 경험 순으로 적용한다. 공고의 문구가 지원자 경험보다 우선하여 경험을 바꾸게 하지는 않는다. 출처가 오래되었거나 권위·현재성이 확인되지 않으면 회사 사실로 쓰지 않고 확인 대상으로 남긴다.

| 공고 또는 검증 출처의 요구 | 지원자 근거 | 처리 |
| --- | --- | --- |
| 요구와 직접 연결되는 확인된 행동·산출물·결과 | 주장 ID와 확인 상태가 있다 | 연결 문장을 쓸 수 있다. 연결이 파생이면 근거 ID를 적는다. |
| 공고 키워드는 있으나 지원자 근거가 없다 | 없음·모순·금지 | 근거 공백으로 보고하고 확인 질문을 한다. **지원자 근거 없는 키워드 일치는 맞춤이 아니다.** |
| 회사 고유 사실 | 사용자가 제공했거나 요청한 검증 출처의 구체적 사실 | 블라인드·문항 제약을 통과할 때만 제한적으로 연결한다. |

검증되지 않은 회사 키워드는 사용하지 않는다. 회사명만 바꿔도 성립하는 문장은 직무 요구와 지원자 근거를 더 구체적으로 연결할 수 있는지 점검하되, 확인되지 않은 회사 정보로 보강하지 않는다.

## 요청된 분량의 확인과 선택

문항의 글자 제한은 문항 필수 요소, 사실 근거, 블라인드 규칙보다 앞서는 면허가 아니다. 분량·글자 수가 요청되었거나 문항이 제한을 제시하면, 문장 수준 감사를 마친 실제 본문을 `scripts/count_chars.py`로 표준입력에 보내 내부 확인한다. 적용 기준과 실제 수치는 사용자가 글자 수 확인·분량 조정·검토를 요청했을 때에만 함께 보인다.

제한 안에 모든 필수 문항 요소와 각 요소의 최소 근거를 보존할 수 없으면, 분량 검토나 선택지를 요청한 경우에만 **트레이드오프**를 분명히 보여 준다. 무엇이 필수인지, 어느 근거 또는 설명을 줄이면 무엇을 잃는지, 현재 글자 수와 제한을 함께 제시하고 선택을 요청한다. 본문만 요청한 경우에는 본문 외 표를 붙이지 않되, 해결되지 않은 핵심 사실이나 제출 불가능한 제약은 숨기지 않는다. 중요 요소를 조용히 삭제하거나, 짧게 만들기 위해 새로운 요약 사실·인과·수치를 발명하지 않는다.

제출 전에는 지원자가 표식 해소 여부, 모든 주장과 파생 근거, 글자 수 범위, 블라인드 준수, 공고·회사 사실의 출처, 자신의 목소리를 직접 확인한다.
